# Данные каталога «Свои — для своих»

`catalog.json` — готовая публичная выдача для существующего каталога Tilda. Это публикационный файл, не самостоятельная редактируемая база.

## Источник и состав

Источниками остаются оригинальные Google-таблицы Союза. Файл получен из уже работающего сборщика, без изменения текстов, телефонов, акций, ID и рубрик.

В исходной публикации 34 компании. Схема ответа — `schemaVersion: 2`, результат успешной сборки — `ok: true`. Логотипы и оформление существующий сайт пока берёт из своих блоков Tilda, не из этого файла.

Здесь не размещаются оригинальные таблицы, заявки посетителей, пароли и токены. Файл содержит только ту публичную выдачу, которая уже используется каталогом.

## Обновление

1. Получить новую успешную выдачу существующего сборщика.
2. Проверить схему, уникальность BusinessID и соответствие количества элементов полю `count`.
3. Заменить `catalog.json` целиком. Не редактировать отдельные компании здесь: исправления вносятся в оригинальные источники по правилам проекта.
4. При ошибке сборки не заменять предыдущую исправную выдачу. Не публиковать ответ `ok: false`.
5. При неизменном `hash` новое изменение файла не требуется.

## Ежедневное обновление

Файлы автоматизации: `.github/workflows/update-catalog.yml` и `update-catalog.mjs`. Запуск запланирован раз в сутки на 06:17 по Ноябрьску (01:17 UTC). Его выполняет GitHub Actions, без участия ИИ и без посещения сайта.

GitHub обращается к существующему публичному Google Apps Script. Тот выполняет прежние проверки допуска и согласованных версий. Дополнительно перед публикацией проверяются схема, хеш содержимого, ID, телефоны, ссылки и все 12 известных сайту рубрик.

При неизменном хеше `catalog.json` не перезаписывается. При ошибке чтения, неуспешной сборке или неверных данных новая выдача не публикуется. Замена успешной выдачи выполняется целиком с проверкой прежнего SHA файла.

Время указано как расписание запуска, не как гарантия завершения. Синтаксис расписания и права автоматического токена описаны в [документации GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).

GitHub автоматически останавливает расписания публичных репозиториев после 60 дней без активности: [официальное ограничение](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows). Поэтому после 45 дней без каких-либо коммитов предусмотрена пустая служебная отметка активности. Она не меняет и не перезаписывает данные каталога; при обычных обновлениях не нужна.

Для ручного запуска: вкладка **Actions** → **Daily catalog update** → **Run workflow**, ветка `main`. Результат находится в журнале запуска и его Summary. При ошибке нужно открыть красный запуск; публикация Tilda для исправления данных файла не требуется.

Для остановки: **Actions** → **Daily catalog update** → меню **…** → **Disable workflow**. Для изменения времени отредактировать только строку `cron` в `.github/workflows/update-catalog.yml`; время в ней указано в UTC.

Используется временный `GITHUB_TOKEN`, выдаваемый GitHub самому запуску. Личный токен пользователя, ключ GitHub в Apps Script или токен в публичном сайте не нужны.

Логотипы, словарь рубрик и оформление эта автоматизация не добавляет. Неизвестная рубрика блокирует замену файла, пока сайт явно не подготовлен к ней.

## Подключение и восстановление

Адрес публичного файла используется как `ENDPOINT` в существующем коннекторе блока 03 Tilda. Посетитель скачивает готовые данные; посещение не запускает сборку таблиц.

Для изменения данных файла повторная публикация Tilda не требуется. Изменение самого кода Tilda, оформления или встроенных логотипов требует отдельного обновления соответствующих блоков.

Для восстановления предыдущей исправной выдачи используется история `catalog.json` в GitHub. Нельзя помещать ключ GitHub в публичный блок Tilda.
